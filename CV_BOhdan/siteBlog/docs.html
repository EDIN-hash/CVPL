2. Архитектура разделения потоков

Чтобы математика хайпа не ломалась от разнородных данных, система делит входящий поток на две независимые категории:

  • SOCIAL_HYPE: Hacker News и Reddit. Использует сложную формулу скорости (Velocity), MAD-рейтинг, коэффициенты дискуссионности и экспоненциальный спад времени.
  • OFFICIAL_UPDATES: Steam News API. Исключает надуманные метрики лайков, ранжируя патчи по свежести и типу обновления.

3. Инфраструктурные лимиты Cloudflare Free

Бесплатный тариф накладывает жесткие рамки, которые учтены в коде:

  • Максимум 50 внешних subrequests за один запуск воркера.
  • Оптимизация: парсер забирает ровно 30–40 постов пачками через Promise.all.

SQL Schema
DROP TABLE IF EXISTS hype_posts;

CREATE TABLE hype_posts (
  source TEXT,
  source_type TEXT DEFAULT 'SOCIAL',
  external_id TEXT,
  title TEXT,
  url TEXT,
  score INTEGER,
  comments INTEGER,
  hype INTEGER,
  created_at INTEGER,
  first_seen_at INTEGER,
  last_seen_at INTEGER,
  PRIMARY KEY(source, external_id)
);

export default {
  async fetch(request, env) {
    if (request.method === "OPTIONS") return new Response(null, { status: 204, headers: corsHeaders });
    const url = new URL(request.url);

    if (url.pathname === "/force-sync") {
      await this.processFeed(env);
      return new Response(JSON.stringify({ status: "Synced" }), { headers: corsHeaders });
    }
    
    const { results } = await env.DB.prepare("SELECT * FROM hype_posts ORDER BY hype DESC LIMIT 100").all();
    return new Response(JSON.stringify(results), { headers: corsHeaders });
  },

6. GitHub Actions Workflow (CI/CD)

.github/workflows/deploy.yml
name: Deploy GitHub Pages

on:
  push:
    branches: [ "main", "master" ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with: { path: '.' }
      - uses: actions/deploy-pages@v4
